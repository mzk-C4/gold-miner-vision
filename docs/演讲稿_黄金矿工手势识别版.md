# 黄金矿工 — 手势识别版 项目讲解与汇报演讲稿

---

## 开场

各位老师、同学，大家好！

今天我汇报的项目是"黄金矿工 — 手势识别版"。这是一款基于经典黄金矿工游戏的现代化重构，核心亮点是引入了手势识别控制，让玩家可以脱离键鼠，用手部动作来操控游戏。

下面我将从项目整体架构出发，逐一介绍每个程序模块的功能、使用方式和它们之间的关系。

---

## 一、项目全景

整个项目分为三个主要部分：

1. **cocos2d-proj** — 游戏主体，基于 Cocos2d-x 4.0 引擎开发的 C++ 桌面游戏，包含游戏逻辑、手势识别服务和全部资源文件。
2. **frontend** — 一套基于 Vite + Tailwind CSS 的 PPT 演示前端，用于项目汇报和展示。
3. **doc** — 版本变更日志和文档。

技术栈概览：游戏引擎 Cocos2d-x 4.0，语言 C++17，手势识别用 OpenCV 4.5.5 + 云端 AI 视觉 API，构建工具 CMake，前端用 Vite 7 + Tailwind CSS 3。

## 二、cocos2d-proj — 游戏主程序

这是整个项目的核心。我将按模块逐一讲解。

### 2.1 主场景模块（MainScene）

主场景模块包含游戏运行过程中的所有界面场景，核心文件都放在 `Classes/MainScene/` 目录下。

#### MainRoot — 主菜单/启动页

**文件**：`MainRoot.cpp` / `MainRoot.hpp`

**功能**：游戏的入口界面。玩家一启动游戏看到的就是这个画面 — 有矿工动画、云朵飘动、开始按钮。

**使用方式**：
- 点击"开始"按钮进入游戏
- 可以选择输入模式：有三种模式按钮 — **触摸模式**（传统键鼠/触摸）、**OpenCV 模式**（本地摄像头手势识别）、**AI 模式**（云端大模型手势识别）
- 支持多玩家管理：可以创建、切换、删除玩家档案，每个玩家的金币和关卡进度独立存储

**关键设计**：模式选择按钮在菜单页就完成了输入模式的预设，选定的模式会被传递到后续的游戏场景中。

#### Game — 游戏主逻辑

**文件**：`Game.cpp` / `Game.hpp`

**功能**：这是整个游戏的"心脏"，管理钩子摆动、释放、矿物抓取、计时器、分数计算等全部游戏流程。

**使用方式**：

- **触摸/键盘模式**：按空格键释放钩子，按 B 键使用炸药，按 Esc 暂停
- **手势模式**：手掌张开时钩子跟随手部倾斜方向摆动（角度范围 -65 度 到 +65 度），握拳释放钩子，长时间握拳（超过 1.5 秒）引爆炸药
- 游戏画面左上角显示当前关卡目标金额、已获金额和剩余时间
- 抓到矿物后钩子会自动回收，不同矿物重量不同、回收速度不同

**核心机制**：
- 钩子状态机：摆动 → 释放 → 伸出 → 碰撞检测 → 回收
- 碰撞物理：使用 Cocos2d-x 内置物理引擎，钩子碰到矿物触发物理碰撞回调
- 手势角度更新：每帧调用 updateGestureAngle，从融合器获取最新手势指令
- 摄像头预览：手势模式下游戏内显示小窗口摄像头画面

**输入模式**：枚举类型 InputMode 包含 TOUCH、OPENCV、AI 三种，运行时可通过 switchInputMode 切换。

#### Shop — 商店系统

**文件**：`Shop.cpp` / `Shop.hpp`

**功能**：每关结束后进入商店界面，玩家可以用赚到的金币购买道具，为下一关做准备。

**使用方式**：
- 点击道具图标查看道具描述
- 选中后点击购买按钮
- 道具效果在下一关自动生效

**四种道具**：

| 道具 | 价格 | 效果 |
|------|------|------|
| 炸药 | 150 金币 | 抓到重物时可以炸毁，节省回收时间 |
| 力量药水 | 200 金币 | 提升钩子拉力，回收重物更快 |
| 钻石升值书 | 300 金币 | 钻石价值翻倍 |
| 矿石收藏书 | 100 金币 | 石头也能卖钱 |

#### Pause — 暂停界面

**文件**：`Pause.cpp` / `Pause.hpp`

**功能**：游戏暂停弹窗，可以控制音乐和音效开关。

**使用方式**：按 Esc 或点击暂停按钮弹出，可切换背景音乐和音效的静音状态，继续游戏或返回主菜单。

#### StageTipsLayer — 关卡提示

**文件**：`StageTipsLayer.cpp` / `StageTipsLayer.hpp`

**功能**：显示关卡开始前的提示信息，告知玩家本关目标金额和时间限制。

### 2.3 服务层模块（services） — 手势识别的核心

这是项目最有技术含量的部分，实现了三种手势识别引擎和一套融合架构。

#### IGestureRecognizer — 手势识别器抽象接口

**文件**：`IGestureRecognizer.hpp`

**功能**：定义所有手势识别器必须实现的统一接口，是策略模式的核心。

**接口方法**：
- `start()` / `stop()` — 启动和停止识别器
- `setCallback(cb)` — 注册结果回调函数
- `pushFrame(jpegData)` — 推送一帧 JPEG 图像用于识别（异步，立即返回）
- `isRunning()` — 查询运行状态
- `name()` — 返回识别器名称（调试用）

**设计理念**：帧推送与结果回调完全异步，识别器内部自行管理线程，不阻塞游戏主线程。

#### LocalGestureRecognizer — 本地 OpenCV 识别器

**文件**：`LocalGestureRecognizer.cpp` / `LocalGestureRecognizer.hpp`

**功能**：使用 OpenCV 在本地完成手势识别，高频实时（约每 30ms 一帧）。

**识别流程**：
1. HSV 颜色空间分割 — 提取肤色区域
2. 轮廓检测 — findContours 获取手部轮廓
3. 凸包分析 — convexHull 识别指尖数量
4. 手势判断 — 指尖数大于阈值判定为张开手掌，否则为握拳
5. 角度计算 — 手部重心偏移映射为钩子角度
6. 时域去抖 — 连续多帧一致才输出结果，防止误触发

**使用条件**：需要佩戴彩色手套辅助肤色分割，对光照条件有一定要求。

#### CloudGestureRecognizer — 云端 AI 识别器

**文件**：`CloudGestureRecognizer.cpp` / `CloudGestureRecognizer.hpp`

**功能**：将摄像头画面发送到云端 AI 视觉 API 进行高精度手势识别，作为本地识别的"双保险"。

**工作方式**：仅在本地检测到握拳（FIST）时才触发云端请求，确认是否真的握拳。这样做的好处是减少网络请求频率，只在关键时刻校验。

**容错设计**：云端超时或失败时自动降级为仅使用本地结果；云端与本地结果不一致时放弃本次触发（安全优先）。

#### AIGestureRecognizer — AI 大模型识别器

**文件**：`AIGestureRecognizer.cpp` / `AIGestureRecognizer.hpp`

**功能**：第三种识别模式，摄像头画面直接发送给豆包 Vision 大模型，由大模型完成手势分类和手部定位。

**架构差异**：和本地+云端双通道模式不同，AI 模式完全跳过 OpenCV/MediaPipe 管线，由大模型一步到位输出手势类型和手部位置。

**角度映射**：归一化手部 X 位置 [-1, +1] 映射为钩子角度 [-65 度, +65 度]。

**配置方式**：需要设置 endpointId 和 apiKey，调用豆包 API。

#### GestureFusion — 手势融合器

**文件**：`GestureFusion.cpp` / `GestureFusion.hpp`

**功能**：整个手势系统的"大脑"，协调本地和云端两个识别引擎的结果，输出最终的游戏指令。采用单例模式。

**融合逻辑**：
- 手掌张开（OPEN_PALM）：直接使用本地角度输出，因为瞄准需要高频实时响应，云端校验没有必要
- 握拳（FIST）首次检测：触发云端请求，等待确认
- 握拳云端确认：释放钩子
- 云端超时：降级为仅信任本地结果
- 云端与本地不一致：放弃本次触发（安全优先）

**输出的 GestureCommand 包含**：
- shouldReleaseHook — 是否释放钩子
- shouldDetonateBomb — 是否引爆炸药（握拳超过 1.5 秒）
- targetAngle — 钩子目标角度
- isValid — 指令是否有效

**时间控制**：两次释放钩子最小间隔 0.8 秒（冷却时间），握拳持续 1.5 秒以上引爆炸药。

**AI 独占模式**：调用 initializeAI() 进入 AI 模式后，融合器直接使用 AIGestureRecognizer 的结果，跳过双通道逻辑。

#### GestureClient — 手势客户端

**文件**：`GestureClient.cpp` / `GestureClient.hpp`

**功能**：游戏与手势服务器之间的 HTTP 通信客户端，使用 libcurl 实现网络请求。

#### GestureData — 手势数据结构

**文件**：`GestureData.hpp`

**功能**：定义手势识别相关的数据结构。

- GestureType 枚举：OPEN_PALM（张开手掌）、FIST（握拳）、UNKNOWN（未知）
- GestureResult 结构体：原始识别结果，包含手势类型、角度、置信度、稳定性标记等
- GestureCommand 结构体：融合后的高层指令，直接被游戏逻辑消费

#### PlayerManager — 玩家管理器

**文件**：`PlayerManager.cpp` / `PlayerManager.hpp`

**功能**：管理多玩家档案，也是单例模式。

**使用方式**：
- selectPlayer(name) — 选择玩家
- createPlayer(name) — 创建新玩家
- deletePlayer(name) — 删除玩家
- addHistory(stageNum, score, targetMoney, passed) — 记录每关结果
- saveProfile() / loadProfile() — 持久化到本地存储

每个玩家独立保存金币、关卡进度和历史记录。

#### LevelLoader — 关卡加载器

**文件**：`LevelLoader.cpp` / `LevelLoader.hpp`

**功能**：从 JSON 文件加载关卡配置。

**关卡数据来源**：`Resources/level_data.json`，定义了 5 个关卡，每个关卡包含目标金额、时间限制和矿物分布。

### 2.6 GestureServer — 手势识别服务端

**目录**：`cocos2d-proj/GestureServer/`

包含两个独立的服务端程序：

#### server.py — Python Flask + MediaPipe 服务

**文件**：`GestureServer/server.py`

**功能**：基于 Flask 框架的 Web 服务，使用 MediaPipe Hand Tracking 进行手势识别，与 C++ 游戏通过 HTTP REST API 通信。

**使用方式**：
```bash
python server.py
```

启动后访问 http://localhost:5000 可以看到摄像头实时画面和手势识别结果。

**API 接口**：
- GET /gesture — 返回当前手势识别结果（角度、手势类型、连接状态）
- GET /frame — 返回 JPEG 快照
- GET /video_feed — 返回 MJPEG 实时视频流

**工作原理**：
- 使用 MediaPipe Hands 模型检测手部关键点
- 根据指尖和指关节位置关系判断手势（张开/握拳）
- 计算手部位置映射为钩子角度
- 实时绘制手部骨骼和关键点到画面上

#### main.cpp — C++ GestureServer

**文件**：`GestureServer/main.cpp`

**功能**：C++ 版本的手势识别服务端，使用 OpenCV 采集摄像头画面并编码为 JPEG，供游戏客户端拉取。

## 三、frontend — PPT 演示前端

**目录**：`frontend/`

这是一个基于 Vite 7 + Tailwind CSS 3 的 PPT 演示系统，用于项目汇报展示。

**技术栈**：Vite 7（构建工具）、Tailwind CSS 3（样式框架）、原生 JavaScript ES6+（模块化开发）、PostCSS（CSS 后处理）。

**使用方式**：
```bash
cd frontend
npm install
npm run dev       # 启动开发服务器，默认端口 5173
npm run build     # 构建生产版本，输出到 dist/
npm run preview   # 预览生产构建
```

**功能特性**：
- 幻灯片切换动画（淡入淡出）
- 键盘导航（方向键、空格、Home/End）
- 触摸滑动支持（移动端）
- 进度条和页码指示器
- 16:9 自适应布局
- CSS 变量主题系统

**幻灯片数据管理**：每页幻灯片内容存储在 `src/data/slide-N.js` 中，通过全局 `window.slideDataMap` 注册，PPTController 负责加载和渲染。添加新幻灯片只需创建新的 slide-N.js 文件并在 index.html 中引入即可。

**核心文件**：
- `src/js/ppt-controller.js` — PPT 控制器，处理导航、动画和事件
- `src/js/route-handler.js` — 路由处理器，404 重定向
- `src/styles/main.css` — 主样式
- `src/styles/unified-styles.css` — 幻灯片统一样式库
- `scripts/build-slides.js` — 构建脚本

## 四、设计模式亮点

项目在架构上运用了三种经典设计模式，值得特别提一下：

1. **策略模式**：IGestureRecognizer 定义统一接口，LocalGestureRecognizer、CloudGestureRecognizer、AIGestureRecognizer 分别实现。支持运行时切换识别策略，符合开闭原则。

2. **单例模式**：GestureFusion、PlayerManager、MusicPlayer、LevelLoader 都是全局唯一实例，确保状态一致性。

3. **观察者模式**：手势识别器通过 ResultCallback 回调机制将结果推送给上层，解耦识别器和使用者。
